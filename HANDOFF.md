## Что это за проект
iOS-приложение **«Уголёк» (Ugolek)** — автоматически продлевает «огоньки» (стрики) в TikTok: в назначенное время открывает веб-инбокс `tiktok.com/messages` в скрытом WKWebView и рассылает сообщения друзьям. Clean-room переписывание с нуля (не копия форка `D:\modtt` / TiktokStreakSaver, хотя идея оттуда; в README есть «inspired by»).

- **Локальный репозиторий:** `D:\Ugolek`. **GitHub:** `Noli4ekc/ugolek` (публичный).
- **Стек:** Swift/SwiftUI, iOS 17+, генерация проекта XcodeGen (`project.yml`), ноль сторонних зависимостей.
- **Сборка:** GitHub Actions (macOS-раннер, бесплатно): compile-check + артефакт `Ugolek-unsigned-ipa` + симуляторный zip + **rolling-release** (job сам прикрепляет свежий IPA к релизу `rolling` при каждом пуше в main).
- **Установка пользователю (Кирилл):** через **Sideloadly** на его Windows-ПК. Всё сложено в `D:\sideload-tools\` (там же установщики iTunes/Sideloadly и свежий `Ugolek-unsigned.ipa` — я обновляю его curl'ом из rolling-релиза после каждой сборки).
- **Планирование:** Task Master в `D:\Ugolek\.taskmaster\tasks\tasks.json` — 33 задачи; выполнены 1–23, 28, 33; остались 24–27, 29–32 (Этапы F и G).

## Проверенные факты о TikTok DOM (2026-08-22; залогиненное состояние; окно 1920×1080)
- Список чатов: `[data-e2e='dm-new-conversation-item']`; внутри `a[href*='/@']` (юз), `[data-e2e='dm-new-conversation-nickname']` (ник), у строки есть `data-conv-id`, `aria-selected` при клике.
- **Список перерисовывается вживую** (виртуализация, новые сообщения, unread-счётчики) → ноды устаревают за секунды. Кликать только по свежепере-найденной ноде (`data-conv-id`/ник), иначе клики уходят в отсоединённый от DOM элемент, а `aria-selected=true` остаётся с ранней попытки (причина плавающего «чат не открылся»).
- `[data-e2e='dm-render-error']` — error boundary DM-области. В видимом состоянии показывает оверлей «Something went wrong / Sorry about that!» и прячет ВСЮ правую панель (исчезает даже inbox → `панель=[ничего]`). **Может появляться сам, до любого клика** (m4.16) и переживать перезагрузку страницы — значит дело в окружении (UA/Chrome-only API, битое localStorage) или в восстанавливаемом TikTok разговоре. Лечится: кнопка повтора в оверлее, клик по другому чату (перемонтирует панель), очистка сайтовых данных, смена UA. **Опасно:** наш `clickViaReact` (фейковое React-событие с `nativeEvent:{}`) мог сам ронять DM-приложение — убран в m4.16.
- **UA движка:** десктопный Safari (Mac) — не Chrome! WKWebView это WebKit, а TikTok под Chrome-UA может звать Chrome-only API (userAgentData) и ронять DM-панель. `SessionStore.desktopUserAgent` = Safari 17.4; движок использует его напрямую, игнорируя сохранённый при логине UA.
- Список появляется **с задержкой** (может >3 с) — ждём до 15 с (`waitForChatList`).
- Поле ввода: Draft.js `contenteditable.notranslate.public-DraftEditor-content` внутри `[data-e2e='dm-new-input-editor']`. Запасной путь: textarea в `[data-e2e='message-input-area']`.
- Кнопка отправки: элемент с `data-e2e` содержащим `send` — оказалась **SVG** (нет `.click()`) → сделан `safeClick` через события мыши.
- Пузыри сообщений: `[data-e2e='dm-new-message-text']`.
- **Разлогин не редиректит на /login**: страница показывает `[data-e2e='top-login-button']` → после загрузки проверяем и инвалидируем сессию (`SessionStore.invalidate`).
- **Огонёк (стрик) в веб-версии НЕ отображается вообще** (проверено полным сканированием DOM) → ручной флажок `Friend.hasFlame` + настройка «Только тем, у кого есть огонёк». Погасший огонёк восстановим (TikTok официально имеет Restore) → флажок держим включённым.
- TikTok **катит разные сборки вёрстки на живую** (хэши CSS-классов меняются между сессиями) → поведение «плавает».
- Десктопная раскладка (1920×1080) обязательна: на «средних» ширинах (1280) клик по чату не открывает панель; на 390 (мобильная) — чат-«экран» мог сбежать.

## Кнопка 🔥 в Пункте управления — как это реализовано на самом деле (2026-08-25)
План `docs/control-center-plan.md` частично ошибался. Проверено CI-диагностикой и Apple-доками:

1. **`ControlWidget` НЕ компилируется в main app target** — нужен отдельный **Widget Extension target** (`type: app-extension`). В `project.yml` это таргет `UgolekWidget` (bundle id `com.ugolek.app.widget`, deployment target iOS 18.0), главный таргет его встраивает (`dependencies: [target: UgolekWidget]`), схема собирает оба.
2. **Нужны ОБА импорта: `import SwiftUI` + `import WidgetKit`.** Протоколы (`ControlWidget`, `ControlWidgetConfiguration`) живут в SwiftUI, структуры конфигурации (`StaticControlConfiguration(kind:content:)`, `ControlWidgetButton`) — в WidgetKit. Поодиночке импорты дают «cannot find type» (интерфейс WidgetKit не грузится без SwiftUI из-за `ControlWidgetTemplate`). Это была главная ловушка.
3. `MaintainStreaksIntent.swift` общий для обоих таргетов; вызов `RunCoordinator.shared.start()` обёрнут в `#if !WIDGET_EXTENSION` (в расширении RunCoordinator нет). `UgolekShortcuts` тоже под `#if !WIDGET_EXTENSION`.
4. `UgolekControlWidget.swift` исключён из sources главного таргета (`excludes:` в project.yml) и входит только в виджетный.
5. CI: Xcode зафиксирован на **16.4** (`setup-xcode`, latest-stable нестабилен). Ручные Info.plist для расширения не создавать — XcodeGen генерит сам (путь указан через `info.path: UgolekWidget/Info.plist`; файл появится при `xcodegen generate`). Чужой plist внутри рекурсивного глоуба `path: Ugolek` даёт «Multiple commands produce Info.plist».
6. Bundle ID приложения сменён авто → `com.ugolek.app` (`PRODUCT_BUNDLE_IDENTIFIER` в settings.base). При установке поверх старого iOS считает это другим приложением: **сначала удалить старый Уголёк** (куки TikTok в Keychain сотрутся — перелогин).

Симуляторный compile-check собирает оба таргета успешно; device-archive кладёт `.appex` внутрь IPA (два bundle — Sideloadly должен ре-сайнить оба).

## Фоновые режимы продления огоньков — реализовано 2026-08-25
План `docs/background-modes-plan.md` выполнен (этапы A–C, E). Три уровня:

1. **Гео-держатель прогона** (всегда включён): `LocationKeeper` (CoreLocation, точность 3 км,
   `allowsBackgroundLocationUpdates`, watchdog 15 мин) арендуется в `RunCoordinator.start()` на время
   любого прогона. После тапа 🔥 можно свернуть/заблокировать телефон — прогон дойдёт до конца.
2. **Фоновый интент для Команд**: `HeadlessStreaksIntent` («Продлить огоньки (фон)», `openAppWhenRun=false`)
   + `RunCoordinator.startHeadless()` без UI. Автоматизация «Время суток» в Командах запускает прогон
   без открытия приложения; итог — уведомлением. На заблокированном телефоне Шорткатс ждёт разблокировки.
3. **Тумблер «Гео всегда» в настройках** (`AppSettings.geoAlwaysAuto`): постоянная аренда локации +
   `AutoRunner` стреляет прогоном в время напоминалки ±15 мин дрожания. При включении — тестовый dry-run
   (`StreakEngine.run(dryRun: true)`), провал отщёлкивает тумблер с уведомлением. Отзыв разрешения
   гасит режим через `geoPermissionRevoked`. После ребута оживается при первом открытии приложения.

### Как теперь работает доставка
1. **Один проход скролла оценивает каждого друга по ДВУМ иглам** (юзернейм ранг 1/3,
   имя из label ранг 2/4) → кандидаты сортируются по рангу.
2. Каждый кандидат: re-resolve по data-conv-id (React перерисовывает список) → открыть →
   **прочитать юзернейм в открытой панели** (ссылка /@ или текстовый «@login»).
   Не совпал / не прочитался → следующий кандидат. Никогда не отправляем вслепую.
3. После совпадения юза — **скип если сегодня уже писали обе стороны** (threadTodayFlags
   ищет разделитель дат «Сегодня» в треде; направления сообщений — геометрия справа/слева).
   Только он написал → пишем (ответ спасает стрик). Только ты → скип (повтор бесполезен).
   Разделителя не видно (виртуализация) → пишем (безопасный дефолт).
4. **Не найден** → ProfileFetcher (tiktok.com/@handle, embedded JSON, uniqueId-матч) →
   свежий ник → обновление label → ОДИН retry. Страница не открылась → честно
   «Страничка не найдена» в истории (не путать со сменой юзернейма).

### Тумблер и запасные пути
- Настройки → Доставка → «Проверять получателя» (ВКЛ). Выключить при массовых
  «не удалось проверить» в истории → старый поиск по имени (первый совпавший).
- Счётчик непроверяемых кандидатов пишется в лог прогона.
- Свайп по другу: «🔥 Продлили сами» (lastSentDay=сегодня) / «↺ Вернуть в очередь».
- Добавление друга: ник подтягивается сам (debounce 800 мс), ручные правки метки
  не затираются; для групп имя по-прежнему руками.

## Проверка имени — фиксы по адверсариальному ревью (2026-08-26, Night)
Агент нашёл 16 атак в проверке имени (`docs/adversarial-review-nickname.md`). Закрыты:

- **NICK-01/03**: профильные загрузки теперь `makeKey: false` — клавиатура редактора больше не
  крадётся; `nickTask` отменяется при `onDisappear` → каскад не стреляет после закрытия шита.
- **NICK-02**: `decodeUnicodeEscapes` обрабатывает суррогатные пары эмодзи — замена на U+FFFD
  вместо молчаливой потери.
- **NICK-04**: автозаполнение сравнивает метку с ПРЕЖНИМ `autoFilledLabel`, а не с новым —
  ручные правки больше не «затираются» повторным авто-значением.
- **NICK-05**: 404 теперь честно `.missing`, прочие не-200 — `.blocked` (не混淆 бот-фильтр с
  несуществующим профилем).
- **NICK-06**: суточный негативный кэш (`missingUntil`) для мёртвых профилей; триггер retry
  сужен до «в списке чатов» — верификационные ошибки больше не дёргают профильный запрос.
- **NICK-08/09**: raw-фолбэк стал регистронезависимым и корректно парсит `\"` внутри ника.
- **NICK-11**: Part B обновляет label по СВЕЖЕЙ копии из AppStore, а не по snapshot'у из цикла.
- **NICK-12**: переключение на группу сбрасывает ник-статус.
