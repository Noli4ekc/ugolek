## Что это за проект
iOS-приложение **«Уголёк» (Ugolek)** — автоматически продлевает «огоньки» (стрики) в TikTok: в назначенное время открывает веб-инбокс `tiktok.com/messages` в скрытом WKWebView и рассылает сообщения друзьям. Clean-room переписывание с нуля (не копия форка `D:\modtt` / TiktokStreakSaver, хотя идея оттуда; в README есть «inspired by»).

- **Локальный репозиторий:** `D:\Ugolek`. **GitHub:** `Noli4ekc/ugolek` (публичный).
- **Стек:** Swift/SwiftUI, iOS 17+, генерация проекта XcodeGen (`project.yml`), ноль сторонних зависимостей.
- **Сборка:** GitHub Actions (macOS-раннер, бесплатно): compile-check + артефакт `Ugolek-unsigned-ipa` + симуляторный zip + **rolling-release** (job сам прикрепляет свежий IPA к релизу `rolling` при каждом пуше в main).
- **Установка пользователю (Кирилл):** через **Sideloadly** на его Windows-ПК. Всё сложено в `D:\sideload-tools\` (там же установщики iTunes/Sideloadly и свежий `Ugolek-unsigned.ipa` — я обновляю его curl'ом из rolling-релиза после каждой сборки).
- **Планирование:** Task Master в `D:\Ugolek\.taskmaster\tasks\tasks.json` — 33 задачи; выполнены 1–23, 28, 33; остались 24–27, 29–32 (Этапы F и G).

## Проверенные факты о TikTok DOM (2026-08-22; залогиненное состояние; окно 1920×1080)
- Список чатов: `[data-e2e='dm-new-conversation-item']`; внутри `a[href*='/@']` (юз), `[data-e2e='dm-new-conversation-nickname']` (ник), у строки есть `data-conv-id`, `aria-selected` при клике.
- **Список перерисовывается вживую** (виртуализация, новые сообщения, unread-счётчики) → ноды устаревают за секунды. Кликать только по свежепере-найденной ноде (`data-conv-id`/ник), иначе клики уходят в отсоединённый от DOM элемент, а `aria-selected=true` остаётся с ранней попытки (причина плавающего «чат не открылся»).
- `[data-e2e='dm-render-error']` — error boundary DM-области. В видимом состоянии показывает оверлей «Something went wrong / Sorry about that!» и прячет ВСЮ правую панель (исчезает даже inbox → `панель=[ничего]`). **Может появляться сам, до любого клика** (m4.16) и переживать перезагрузку страницы — значит дело в окружении (UA/Chrome-only API, битое localStorage) или в восстанавливаемом TikTok разговоре. Лечится: кнопка повтора в оверлее, клик по другому чату (перемонтирует панель), очистка сайтовых данных, смена UA. **Опасно:** наш `clickViaReact` (фейковое React-событие с `nativeEvent:{}`) мог сам ронять DM-приложение — убран в m4.16.
- **UA движка:** десктопный Safari (Mac) — не Chrome! WKWebView это WebKit, а TikTok под Chrome-UA может звать Chrome-only API (userAgentData) и ронять DM-панель. `SessionStore.desktopUserAgent` = Safari 17.4; движок использует его напрямую, игнорируя сохранённый при логине UA.
- Список появляется **с задержкой** (может >3 с) — ждём до 15 с (`waitForChatList`).
- Поле ввода: Draft.js `contenteditable.notranslate.public-DraftEditor-content` внутри `[data-e2e='dm-new-input-editor']`. Запасной путь: textarea в `[data-e2e='message-input-area']`.
- Кнопка отправки: элемент с `data-e2e` содержащим `send` — оказалась **SVG** (нет `.click()`) → сделан `safeClick` через события мыши.
- Пузыри сообщений: `[data-e2e='dm-new-message-text']`.
- **Разлогин не редиректит на /login**: страница показывает `[data-e2e='top-login-button']` → после загрузки проверяем и инвалидируем сессию (`SessionStore.invalidate`).
- **Огонёк (стрик) в веб-версии НЕ отображается вообще** (проверено полным сканированием DOM) → ручной флажок `Friend.hasFlame` + настройка «Только тем, у кого есть огонёк». Погасший огонёк восстановим (TikTok официально имеет Restore) → флажок держим включённым.
- TikTok **катит разные сборки вёрстки на живую** (хэши CSS-классов меняются между сессиями) → поведение «плавает».
- Десктопная раскладка (1920×1080) обязательна: на «средних» ширинах (1280) клик по чату не открывает панель; на 390 (мобильная) — чат-«экран» мог сбежать.

**✅ КОНТРОЛЬНАЯ ТОЧКА №2 ЗАКРЫТА (2026-08-23).** Движок работает end-to-end: логин → список чатов → открытие чата → ввод текста → отправка → подтверждение. Корневая причина всех падений панели с m4.17 по m4.20: WebView не был first responder → `document.hasFocus()=false` → TikTok считал ввод «не от пользователя» и сворачивал чат. Лекарство: `window.makeKey()` + `webView.becomeFirstResponder()`. Подтверждено через CDP: `lastBubble="Привет! Не дадим нашему огоньку погаснуть! 🔥"`.

**Дополнительные фиксы сессии (m4.22–m4.25):**
- **Скролл к чатам «внизу» списка (m4.22–m4.23):** `scrollTargetFor()` искал скролл-контейнер среди предков списка — но настоящий контейнер (безымянный `div` с `sH=2748, cH=1024`) находится **внутри drawer**, не среди предков. Исправлено: ищем внутри `[class*="DivDrawerCont"]`. TikTok ограничивает `scrollTop` на 1724 из 2748 — добавлен `scrollIntoView` на последний элемент как фолбэк.
- **Handle недоступен в списке чатов (m4.24):** в веб-списке TikTok нет ссылок `a[href*="/@"]` — handle виден только в открытом чате. Добавлен `fuzzyMatch` (частичное совпадение никнейма и handle).
- **Кириллица vs латиница (m4.25):** никнейм "нн" (кириллица, charCode 1085) ≠ handle `nnnnll67nl` (латиница, charCode 110). Добавлена `normalizeLayout()` — транслитерация кириллических букв-омоглифов к латинице перед сравнением. `fuzzyMatch("nnnnll67nl", "нн")` → нормализация → совпадение.
